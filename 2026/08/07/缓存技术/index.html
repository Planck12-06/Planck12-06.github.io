缓存技术

由于网络带宽和服务器硬件成本的限制，在高并发场景下服务器的性能会受到影响。为了解决这个问题，就需要使用缓存技术。

缓存需要将热点数据提前加载到缓存中，当下一个请求过来时，可以直接从缓存中获取，而不需要从数据库中查询。缓存技术可以提高服务器的性能，减少数据库的压力。

使用示例

执行流程

  1. 查询缓存：先从 Redis 中获取数据
  2. 缓存命中：如果存在且有效，直接返回缓存数据
  3. 缓存未命中：查询数据库获取原始数据
  4. 写入缓存：将查询结果写入 Redis，设置合理的过期时间
  5. 返回结果：将数据返回给客户端

缓存常见问题

缓存穿透

产生原因

用户请求的数据在缓存中和数据库中都不存在，不断发起这样的请求，给数据库带来巨大压力。

解决方案

  • 缓存 null 值：将空结果也缓存，设置较短过期时间
  • 布隆过滤：快速判断数据是否可能存在
  • 增强 id 的复杂度：避免被猜测 id 规律
  • 做好数据的基础格式校验：在入口处拦截非法请求
  • 加强用户权限校验：防止恶意攻击
  • 做好热点参数的限流：保护数据库不被压垮

缓存空值示例

缓存击穿

产生原因

某个热点 Key 过期瞬间，大量并发请求同时打到数据库。

解决方案

  • 互斥锁：只允许一个线程重建缓存
  • 逻辑过期：不设置真正的过期时间，由业务逻辑判断

缓存雪崩

产生原因

同一时段大量的缓存 Key 同时过期或 Redis 服务宕机，导致所有请求打到数据库，带来巨大压力。

解决方案

  • 随机过期时间：避免大量 Key 同时过期
  • 高可用集群：Redis 主从 + 哨兵/集群
  • 限流降级：保护数据库不被压垮
  • 多级缓存：热点数据缓存到 Redis，其他数据缓存到本地缓存
