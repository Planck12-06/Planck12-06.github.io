项目部署(Docker)

发表于2026-07-24|更新于2026-07-27|项目部署
|总字数:3.6k|阅读大概需要时长:13分钟

Docker 引入

在 Linux 上部署一个单体项目非常麻烦，由于每台服务器的运行环境都不同，写好的安装流程、部署脚本并不一定在每一个服务器上都能正常运行。因此需要一个工具来帮助自动化部署，Docker 就是这样一个工具。

命令解读

参数 说明
docker run -d 创建并运行容器，-d 让容器以后台进程方式运行
--name mysql 将容器命名为 mysql
-p 3307:3306 设置端口映射（宿主机端口:容器内端口）。容器是隔离环境，外界不可访问，但可以将宿主机端口映射到容器内端口。容器内端口由进程决定（如 MySQL 默认 3306），宿主机端口可任意指定
-e TZ=Asia/Shanghai 设置时区为上海时区
-e MYSQL_ROOT_PASSWORD=1234 设置 MySQL 的 root 密码
mysql:8 指定镜像名称及版本号，未指定版本则默认使用 latest

执行这条命令后，Docker 会自动搜索并下载 MySQL 镜像，然后运行 MySQL 容器，程序员无需手动干预。并且这条命令可以在不同的操作系统中正常运行，非常方便。

这里下载的不是安装包，而是镜像（Image）。镜像中不仅包含了 MySQL 本身，还包含了其运行所需要的环境、配置、系统级函数库。因此它在运行时就有自己独立的环境，就可以跨系统运行，不需要手动配置环境。这套独立的隔离环境就是容器（Container）。

因此，Docker 安装软件的过程就是：自动搜索下载镜像 → 创建并运行容器。

Docker 官方提供了一个专门管理、存储镜像的网站 Docker Hub，对外开放了镜像上传、下载的权限。Docker 官方提供了一些基础镜像，各大软件公司又在基础镜像基础上制作了自家软件的镜像，全部都存放在这个网站。

像这样提供存储、管理 Docker 镜像的服务器被称为 Docker Registry（镜像仓库）。

总结

Docker 本身包含一个后台服务，利用 Docker 命令告诉 Docker 服务去搜索并下载应用对应的镜像，然后根据镜像创建并运行容器，应用就部署完成了。

数据卷

基础概念

容器是隔离环境，容器内的程序文件、配置、运行时产生的数据都在容器内部。要读写容器内的文件非常不方便，因此程序产生的数据与程序运行依赖的配置都应该与容器解耦。

数据卷（Volume） 是一个虚拟目录，是容器内目录与宿主机目录之间映射的桥梁。

容器内目录与宿主机目录关联起来的操作称为挂载（Mount）。

/var/lib/docker/volumes 这个目录就是默认存放所有容器数据卷的目录，其下再根据数据卷名称创建新目录，格式为 /数据卷名/_data。

为什么不让容器目录直接指向宿主机目录？

  • 直接指向宿主机目录会与宿主机强耦合。如果切换了环境，宿主机目录就可能发生改变。而容器一旦创建，目录挂载就无法修改，这样容器就无法正常工作了。
  • 但是容器指向数据卷（一个逻辑名称），数据卷再指向宿主机目录，就不存在强耦合问题。如果宿主机目录发生改变，只要改变数据卷与宿主机目录之间的映射关系即可。

数据卷常用命令

命令 说明
docker volume create创建数据卷
docker volume ls查看所有数据卷
docker volume inspect查看数据卷详细信息
docker volume rm删除指定数据卷
docker volume prune删除所有未使用的数据卷

注意：容器与数据卷的挂载要在创建容器时配置，对于已创建的容器无法再设置数据卷。而且在创建容器的过程中，如果数据卷不存在会自动创建。

自定义镜像

镜像的结构

之前说过，镜像之所以能实现快速跨操作系统部署应用而忽略其运行环境、配置，就是因为镜像中包含了程序运行需要的系统函数库、环境、配置、依赖。

自定义镜像本质就是依次准备好程序运行的基础环境 → 依赖 → 应用本身 → 运行配置等文件，并且打包而成。

上述步骤中的每一次操作其实都是在生产一些文件（系统运行环境、函数库、配置最终都是磁盘文件），所以镜像就是一堆文件的集合。但需要注意的是，镜像文件不是随意堆放的，而是按照操作的步骤分层叠加而成，每一层形成的文件都会单独打包并标记一个唯一 ID，称为 Layer（层）。

这样做的好处是：如果构建时用到的某些层其他人已经制作过，就可以直接拷贝使用这些层，而不用重复制作（这就是分层复用的思想）。

Dockerfile

由于制作镜像的过程中需要逐层处理和打包，比较复杂，所以 Docker 提供了自动打包镜像的功能。只需要将打包的过程、每一层要做的事情用固定的语法写下来，交给 Docker 去执行即可。而这种记录镜像构建过程的文件就称为 Dockerfile。

Dockerfile 常用指令

指令 说明 示例
FROM指定基础镜像FROM centos:7
ENV设置环境变量，可在后续指令中使用ENV key value
COPY拷贝本地文件到镜像的指定目录COPY ./xx.jar /tmp/app/
RUN执行 Shell 命令，一般是安装过程的命令RUN yum install -y java
EXPOSE声明容器运行时监听的端口（仅声明作用）EXPOSE 8080
WORKDIR设置工作目录WORKDIR /app
ENTRYPOINT镜像中应用的启动命令（容器运行时调用，不可被覆盖）ENTRYPOINT ["java", "-jar", "xx.jar"]
CMD容器运行时默认执行的命令（可被覆盖）CMD ["java", "-jar", "xx.jar"]

Docker Compose

部署一个简单的 Java 项目，其中就包含 3 个容器：

  • MySQL
  • Nginx
  • Java 项目

而稍微复杂的项目，其中还会有各种各样的其它中间件，需要部署的东西远不止 3 个。如果还像之前那样手动的逐一部署，就太麻烦了。

Docker Compose 可以实现多个相互关联的 Docker 容器的快速部署。它允许通过一个单独的 docker-compose.yml 模板文件（YAML 格式）来定义一组相关联的应用容器。

基本语法

docker-compose.yml 文件中可以定义多个相互关联的应用容器，每一个应用容器被称为一个服务（service）。由于 service 就是在定义某个应用的运行时参数，因此与 docker run 参数非常相似。
